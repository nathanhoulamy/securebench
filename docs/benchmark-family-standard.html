SecureBench Benchmark Family Standard (Revised)

A practical normalized dataset shape for benchmark packs. Rows stay author-friendly, while SecureBench compiles them into strict resource visibility, materialization, and family-specific evaluation behavior.

Public: visible to harness/agent evaluation_inputs: verifier/runtime only hidden: trusted scorer only Rows stay simple; SecureBench enforces internally
Open Revised Examples Open Tester YAML Standard

Minimal Row Contract

Adapters or native benchmark packs should convert benchmark-native rows into this author-facing shape. The family is the routing decision; SecureBench compiles the row into internal resources with explicit visibility before any agent or checker receives data.

{
  "id": "benchmark/task-id",
  "family": "repo_patch",
  "input": {},
  "assets": [],
  "eval": {},
  "environment": {},
  "metadata": {}
}
Visibility rule: input.* and top-level assets[] are public by construction. eval.* is non-public by construction. Family schemas decide which eval.* fields become evaluation_inputs for a checker/runtime and which remain hidden for trusted scoring only.

Benchmark Manifest

A benchmark manifest defines shared defaults so benchmark rows stay focused on task-specific data. It describes benchmark runtime requirements, not the tested agent implementation.

my-benchmark/
  manifest.yaml
  tasks.jsonl
  assets/
  hidden/

manifest.yaml

SecureBench reads the manifest first, applies defaults, then reads benchmark rows.

Visibility Semantics

The row shape stays simple for authors, but SecureBench should enforce precise internal visibility labels.

Compiled Visibility

These are framework semantics, even when the dataset row does not spell them out.

Author-friendly outside, strict inside
Author fieldInternal visibilityVisible toNotes
input.*publicagent, test sandbox, evaluatorTask instructions, prompts, public tool definitions, and visible context.
assets[]publicagent, test sandbox, evaluatorPublic files/directories. If mount is omitted, destination defaults to path.
eval.checker files / hidden tests / simulator stateevaluation_inputstest sandbox/runtime, not agent workspaceMaterialized only when needed for verification. Prefer read-only materialization.
eval.answer / rubric / reference artifact / gold patchhiddentrusted evaluator/scorer onlyUsed for scoring, redacted from results, never materialized into the agent workspace.
Hidden-test limitation: SecureBench can mount evaluation files read-only to protect integrity. If those files execute candidate code in the same process or filesystem namespace, perfect confidentiality from the candidate code is not guaranteed. Benchmarks that need stronger secrecy should prefer black-box checkers or out-of-process scoring.

Assets and Mounts

asset_roots tell SecureBench where to find assets in the benchmark package. Per-asset mount tells SecureBench where that public asset should appear inside the task workspace. Most assets do not need mount.

{
  "assets": [
    {"path": "auth.log"},
    {"path": "shared/config.yaml", "mount": "app/config.yaml"},
    {"path": "template.zip", "mount": "app/", "mode": "extract"}
  ]
}

assets[]

Top-level assets are always public. Evaluator-only files belong under family-specific eval.* fields.

Default: read-only, public, destination equals path

Environment Contract

Environment remains benchmark/runtime configuration. It defines what the task verifier, repository, browser service, simulator, or desktop task needs. It does not define whether the tested system is Codex, Claude Code, ACP, or another harness.

environment:
  image: python:3.11-slim
  packages: [git]
  env:
    PYTHONPATH: .
  workdir: /workspace/repo
  setup:
    - pip install -e .
  network: none
  materialize_workdir_from_image: false
  timeout_seconds: 600
  resources:
    memory: 2g
    cpus: 2
Rows may override only the environment fields they need. SecureBench should merge row overrides with manifest defaults, while preventing benchmark rows or tester YAML from relaxing required security constraints silently.

Environment Fields

Environment is an open benchmark-owned object, but these keys have framework-defined meaning in current container harnesses.

Runtime setup, not harness identity
FieldFamilyTypeDefaultPurpose
imagecontainer-backed familiesstringrequired by Docker harnessesDocker image used for agent and verifier execution.
workdirterminal_task, repo_patchabsolute path string/workspace or family-specificContainer path where the task workspace/repository is mounted and commands run.
timeout_secondsall families that run commandspositive numberharness/verifier defaultBenchmark-owned task timeout used when no narrower checker timeout is set.
materialize_workdir_from_imageterminal_taskbooleanfalseWhen true, SecureBench creates a temporary container from environment.image, copies environment.workdir into the host task workspace, removes the temporary container, and then runs the normal harness. Use this for terminal tasks whose Docker image prepares required starter state inside the workdir; prefer assets[] for small static public files.
Image workdir materialization is public: when materialize_workdir_from_image is enabled, every file copied from environment.workdir becomes agent-visible starter state and may be modified by the agent. Benchmark images must not place hidden tests, answers, credentials, provider configuration, trusted verifier artifacts, or other non-public data under that workdir. Prefer assets[] for small intentional public files, and reserve image workdir materialization for larger image-prepared public state such as repository checkouts or generated starter datasets. Future standards may add narrower include/exclude copy policies for tasks that should materialize only part of an image workdir.

Family Candidate Output Contracts

SecureBench does not need a separate global artifact section for this standard. Each family owns the shape of the candidate output and the verifier behavior.

Family Outputs

The harness produces a candidate; the family verifier decides how to collect and evaluate it.
